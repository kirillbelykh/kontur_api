# Карта проекта для агентов

Проект автоматизирует работу с Контур.Маркировкой: заказ и загрузку кодов, ввод в оборот, задания для ТСД, агрегацию и печать этикеток BarTender. Заявки из WMS принимает локальный HTTP-мост на порту `8791`; отдельного экрана ЧЗ в интерфейсе нет.

## Структура

| Путь | Назначение |
|---|---|
| `main.py` | минимальная точка входа desktop-приложения |
| `backend/app/` | desktop-оболочка, `ApiBridge`, локальный HTTP-мост и фоновые процессы |
| `backend/auth/` | cookies, Selenium и работа с профилем Яндекс Браузера |
| `backend/kontur/` | REST-запросы Контур и подпись через КриптоПро |
| `backend/services/` | история, обновления, печать и прикладные сценарии |
| `frontend/` | React 19, TypeScript и Vite; готовая сборка хранится в `frontend/dist` намеренно |
| `tests/` | backend-тесты |
| `docs/` | архитектура, разработка и эксплуатация |
| `assets/` | шаблоны этикеток и иконки |
| `data/` | справочные таблицы |
| `archive/` | устаревший интерфейс, который не следует развивать |
| `runtime/` | cookies, логи, резервные копии и состояние; в Git не попадает |

## Поток данных

```text
React → pywebview.api → ApiBridge
WMS → HTTP :8791 → локальный мост → ApiBridge
ApiBridge → auth / kontur / services → внешние сервисы и локальное ПО
```

`full_orders_history.json` хранит локальные дополнительные сведения о заказах. Основной список заказов загружается из Контур.Маркировки.

## Запуск и проверки

```powershell
.\.venv\Scripts\python.exe main.py
```

```bash
uv sync --dev
uv run flake8
uv run mypy .

cd frontend
npm ci
npm run lint
npm run test
npm run build
```

После изменения frontend обязательно пересоберите и закоммитьте `frontend/dist`: рабочие станции получают интерфейс через обычное обновление Git без Node.js.

## Обязательные правила

- Перед изменением изучите существующую реализацию в том же модуле.
- Не расширяйте `archive/legacy_ui`; актуальный интерфейс находится во frontend.
- Не меняйте контракт методов `ApiBridge` без одновременной проверки вызывающего React-кода.
- Не публикуйте `.env`, cookies, токены, сертификаты, логи, резервные копии и файлы из `runtime/`.
- Не включайте headless-режим Selenium по умолчанию: рабочая авторизация использует реальный профиль Яндекс Браузера и скрытие окна средствами Windows.
- Не удаляйте готовую сборку frontend и операторские точки входа `Install.bat`, `Install.exe`, `update.bat`.
- Для фоновых обновлений используйте только fast-forward относительно `origin/main`; локальные настройки рабочей станции не должны попадать в commit.
- После backend-изменений запускайте целевые тесты, `flake8` и `mypy`; после frontend-изменений — lint, тесты и сборку.

Подробности находятся в [архитектуре](docs/ARCHITECTURE.md), [руководстве разработчика](docs/DEVELOPMENT.md) и [руководстве по эксплуатации](docs/OPERATIONS.md).
